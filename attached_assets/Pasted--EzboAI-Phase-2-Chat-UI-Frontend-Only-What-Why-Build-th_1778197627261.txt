 EzboAI Phase 2 — Chat UI (Frontend Only)
What & Why
Build the complete chat interface visually — message bubbles, input bar with all buttons, sidebar with thread list, top bar, quick action chips, typing indicator, empty states. No AI, no database — purely UI with local React state. After this phase, the user can type messages and see them appear as bubbles, switch between local "threads" stored in localStorage, and the UI looks production-ready. Phase 3 then wires the AI backend and Phase 4 wires the database.

This phase establishes every visual pattern and component the rest of the app will reuse.

Steps
Install deps — react-markdown, remark-gfm, react-syntax-highlighter, @types/react-syntax-highlighter, framer-motion, date-fns (for date grouping), nanoid (thread/message IDs).
Type definitions — types/chat.ts: Message { id, threadId, role: 'user'|'assistant'|'system', content, attachments?, createdAt }, Thread { id, title, createdAt, updatedAt }.
Local store — stores/chatStore.ts (Zustand or Context): holds threads, messages, activeThreadId; methods createThread, deleteThread, renameThread, addMessage, setActiveThread. Persists to localStorage with debounce.
MessageBubble component — render a single message with avatar, content (markdown), timestamp on hover, copy button. Use react-markdown + remark-gfm. Code blocks via SyntaxHighlighter with a theme that switches per dark/light.
MessageList component — virtualized if >100 messages (use react-window if needed), otherwise simple flex column with auto-scroll behavior.
InputBar component — textarea with auto-grow (react-textarea-autosize), 4 left icon buttons, send button. On send, calls addMessage then triggers fake AI response after delay.
QuickActionChips component — horizontally scrollable, 8 chips with icons + Bangla labels. Each has a template prop; click pre-fills the input.
Sidebar component — full implementation with grouping, search, 3-dot menu (use DropdownMenu from shadcn).
TopBar enhancements — add editable title (use a small inline editable component), model picker dropdown (placeholder), voice toggle button.
EmptyState component — welcome card with example prompts; clicking a prompt fills the input.
Animations — framer-motion <AnimatePresence> around message list for enter/exit animations.
Auto-scroll hook — useAutoScroll(ref, deps, options) that scrolls to bottom only if user is near bottom.
Mobile drawer — wrap sidebar in shadcn Sheet for mobile; hamburger button in TopBar opens it.
Toast for unimplemented buttons — sonner toast: "এই feature Phase X এ আসছে" when user clicks unwired buttons.
Visual QA — test on desktop and mobile viewports, dark and light modes, with long messages, code blocks, many threads. Take screenshots.
Code review — architect from code_review skill; fix issues.
Mark complete — Phase 3 unblocks.
Critical constraints
Reuse Phase 1's AppShell, TopBar, Sidebar components — extend, don't duplicate.
All Bangla strings hardcoded in components for now (i18n added later if needed).
Keep chatStore provider-agnostic — Phase 3 will plug AI calls into the same store interface.
Don't store secrets/keys anywhere in the frontend.
Use shadcn primitives for all UI elements — no custom button/input.
